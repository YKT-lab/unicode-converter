## データ形式（試作）

`manifest.json` の `schema_version: 2` に、Unicode版・ビルドID・各ファイルの担当区間・件数・バイト数・SHA-256を記録する。各 `page-....json` は `{"v":1,"g":{"14354":[[x,y,w,h],"SVG path data"]}}` のような形式。

輪郭はフォント内部の上向きY軸のまま保存し、viewBoxのみ下向きY軸へ変換してある。閲覧クライアントは `<path transform="scale(1,-1)">` 相当の座標変換で表示する想定。将来の実装時に描画テストで確認する。

1ファイルには基本128コードポイントの範囲を対応させる。圧縮して192KiBを超えるときは担当区間を二等分する。実ファイルは非圧縮JSONで保存し、gzipの値は `zlib.gzipSync(..., {level:9})` による測定値。公開ホストの転送量とは必ずしも一致しない。

## 著作権・配信に関する制約

**101フォントすべての輪郭データの大規模な抽出・再配布条件を確認するまで、SVGデータの一般公開は禁止。**

この試作では生成データをGitHub Actionsの一時ディレクトリだけに書き込み、GitHubリポジトリやArtifactsには入れない。公開するのは件数・容量などの数値レポートだけ。サイトのJS・CSS・GitHub Pagesの公開設定・通常表示はそのまま。

## 次のPhase 2実装条件

1. フォントごとの再配布ライセンスを確認し、許諾のないフォント由来の輪郭は配信しない。
2. 出力データの索引をコンパクトにし、取得済み分割のキャッシュ・最大並列数・通信失敗時の再試行を設計する。
3. 日本語・珍しい文字・記号・結合記号でのSVG座標と形状を検証する。
4. GitHub標準Pagesビルド・Font Coverage Build・Daily Characterからの**公開処理を一本化**し、旧版へ戻せる手順を用意する。
5. 新方式はSVGモードだけを置き換え、通常表示・Scope・コピー・100文字制限・NEWSリンクを維持する。
6. iPad第8世代等の実機でSVG成功率、1/10/100文字の速度、メモリ使用量を確認する。

**メモ：生成成功文字数と、実際に文字として正確に読める文字数は区別する。**
